# 图片直链的访问控制口径（产品决策）

> 决策日期：2026-10-30 · 本篇是**对既有行为的文档化，不改任何行为**
> （对应 docs/audit-report-2026-10-05.md 复查遗留中「直链不校验 is_public 的『UUID 防线』口径写进文档」一项）

AstrNest 对「私密图片」的访问控制是分层的，产品语义为：**公开性校验发生在列表与分发层，直链层的防线是 objectKey 的不可枚举性**。具体口径：相册详情、媒体列表、随机图（`/api/albums/random/{pathSlug}`）与画廊接口在返回前按 `publicAccessible ∧ 非违规`（`AlbumService#isPublicVisible`）过滤，非属主语境连预览图 uuid 列表也做同口径剔除；而直链通路（`/upload/**` 静态映射、`/api/uploads/**`、`/api/public/assets/**`）按 objectKey 直接吐流，不查属主也不查可见性——这是有意为之：objectKey 统一为「日期目录 + `UUID.randomUUID()` 随机文件名」（`storage/StorageObjectKeys`），无签名、无时效，但 UUID 的 122 位随机性使其事实上不可枚举，因此"私密 = 不出现在任何列表/画廊/随机接口"而非"直链加密"，与图床"直链即发布"的定位一致。由此须接受两条边界：其一，直链 URL 一旦外泄，该图片即永久可被任何持有者访问（无吊销手段，删除文件除外）；其二，uuid 是唯一防线，任何接口都不得向未授权方泄露非公开图片的 uuid（列表层过滤即为此而生）。若未来出现强访问控制需求（按人授权、时效链接），应另行走短时效签名 URL 方案，而非在直链层逐请求回库校验。
